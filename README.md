# 🧩 LEMP Stack: Быстрый и надёжный стенд для backend-разработки
Для удобной разработки backend-приложений команде разработчиков нужен готовый стенд, с помощью которого можно вести разработку, запускать тесты и выполнять деплой на dev- и prod-серверы.

Такие стеки обычно включают в себя среду для интерпретации/компиляции кода, а также базу данных (SQL или NoSQL).

Я решил организовать решение, которое позволяет быстро и надёжно поднимать такие стеки. Например, классический LEMP, который включает:

- **L**inux — операционная система
- **N**ginx — веб-сервер и обратный прокси
- **M**ySQL — реляционная база данных
- **P**HP — интерпретатор для серверного кода

Этот проект — моя реализация подхода Infrastructure as Code для развёртывания LEMP-стека.

## ✨ Что умеет этот проект

- 🐘 Устанавливает и настраивает `php-fpm` с поддержкой `mysql`
- 🗄️ Разворачивает `mysql` с базовой настройкой
- 🌐 Разворачивает `nginx` с кастомным конфигом
- 🔄 Использует динамические переменные (`facts`) для гибкой настройки

## ⚙️ Требования к окружению
Проект протестирован и гарантированно работает в следующей конфигурации:

### 💻 На управляющем узле -Control Node (Место, откуда вы запускаете плейбук )
* **Ansible:** `2.16.3` (на этой версии велась разработка. Проверить свою версию: `ansible --version`).
* **Python:** `3.12.3`

### 🖥️ На целевых серверах (из hosts.ini)
* **ОС:** Ubuntu / Debian (плейбук настраивает конфигурацию для Linux систем).
* **Служба SSH:** На каждом сервере должен быть установлен и запущен `ssh-server`.
* **Доступ по ключу:** Управляющий узел должен подключаться к удаленным серверам по SSH-ключу без ввода пароля.
* **Права Ansible-пользователя:** Пользователь, под которым Ansible подключается к серверам (например, пользователь с правами sudo), должен иметь возможность выполнять команды с повышением привилегий (`become: true`) **без запроса пароля** (настройка `NOPASSWD` в sudoers на целевой машине). Это необходимо, так как проект устанавливает пакеты, настраивает базу данных, перезагружает сервисы.

## 📂 Структура проекта
```text
.
├── files/               # Системные конфигурационные файлы
│   └── nginx            # Директория с дефолтным сайтом nginx
├── roles/               # Директория с логикой автоматизации (роли)
│   ├── php              # Роль для установки php-fpm
|   ├── mysql            # Роль для настройки mysql
│   └── nginx            # Роль для настройки nginx   
├── hosts.ini            # Настройки подключения к вашим серверам
├── playbook.yml         # Главный файл для запуска всех ролей
└── requirements.yml     # Внешние роли и коллекции Ansible
```

## 🚀 Как запустить

1. **Клонировать репозиторий:**
```bash
git clone https://github.com/Vitaliy-Yashin/lemp.git && cd lemp
```

2. **Настроить инвентарь в hosts.ini:**
```ini
[lemp_locals]
192.168.92.148  ansible_user=vitaliy ansible_port=22

[lemp_clouds]
130.193.35.157  ansible_user=vitaliy ansible_port=22
```

3. **Установить зависимости:**
```bash
ansible-galaxy install -r requirements.yml --force
```

4. **Настройка пользователей MySQL:**
Отредактируйте файлы под свои цели в `roles/mysql/vault/secret.yml` — установите надежный пароль для root.

🔒 Файл `roles/mysql/vault/secret.yml` зашифрован в целях безопасности. Расшифровать его для редактирования можно следующей командой:
```bash
ansible-vault decrypt roles/mysql/vault/secret.yml 
# Дефолтный пароль: 12345678
```

📝 После этого файл примет следующий вид, доступный для кастомизации. При необходимости вы можете добавить сюда несколько пользователей:
```yaml
# roles/mysql/vault/secret.yml 
mysql_root:
  name: root
  password: '123456789' # Укажите надежный пароль для root!

mysql_db_users:
  - name: php-user # Желаемое имя пользователя, которое будет использовать backend
    password: '123456' # Пароль для этого пользователя
    priv: '*.*:ALL' # Список привилегий (в данном случае — полные права, аналогичные root)
  
  # При необходимости вы можете добавить сюда дополнительных пользователей по аналогии 
```

> 🔒 **Совет по безопасности:** Давать права `*.*:ALL` (доступ ко всем базам данных) — это плохая практика для продакшна. Для реальных проектов рекомендуется ограничить права пользователя только его конкретной базой данных, например: `имя_базы_данных.*:ALL`.

5. **(Опционально) Зашифровать файлы обратно:**
Сделайте это перед отправкой в Git. Используйте команду ниже и задайте свой собственный надежный пароль:
```bash
ansible-vault encrypt roles/mysql/vault/secret.yml 
```

> ⚠️ **ВАЖНОЕ ПРИМЕЧАНИЕ ПО НАСТРОЙКЕ MySQL (Идемпотентность):**
> При первом запуске плейбука для пользователя `root` в MySQL настраивается аутентификация по паролю через Unix Domain Socket (`/var/run/mysqld/mysqld.sock`). 
> 
> По умолчанию в современных ОС Ubuntu/Debian системный root заходит в базу без пароля (через плагин `auth_socket`). Плейбук меняет этот плагин на аутентификацию по паролю (`{{ mysql_root.password }}`).
>
> **Что это значит для вас:**
> * **Первый запуск:** Пройдет успешно, так как Ansible подключится через сокет с правами суперпользователя ОС и задаст новый пароль.
> * **Повторный запуск:** Если ваш плейбук выполняет чистую смену пароля без проверки текущего состояния, повторный коннект через сокет без указания пароля вернет ошибку `Access denied`. Учитывайте это при кастомизации роли MySQL или передавайте `login_password` для повторных запусков.
> 
> **Рекомендация:** После первого запуска рекомендуется закомментировать или удалить задачу в файле `roles/mysql/tasks/main.yml` со следующим именем **Set root's password**:
```yaml
- name: Set root's password # !!!
  ansible.mysql.mysql_user:
    login_user: root
    login_unix_socket: /var/run/mysqld/mysqld.sock
    name: "{{ mysql_root.name }}"
    password: "{{ mysql_root.password }}"
    host: localhost
    state: present
```

6. **Запуск плейбука:**
```bash
ansible-playbook -i hosts.ini playbook.yml --ask-vault-pass 
# Укажите собственный пароль (или дефолтный "12345678", если вы его не меняли)
```
